# 从原书到交互书

## 1. 输入与证据

建立项目内`SOURCE.md`：来源文件/版本、页码或章节定位、使用者提供的使用范围、扫描/OCR缺口、目标年龄与语言。仅给书名时先索取材料。原文事实、教学改编句和推断分列；不要把生成图当作原书证据。

## 2. 整书骨架

逐章表：章节ID、原文依据、人物、地点、进入时知道什么、关键动作、结果、退出状态、下一章开头、尚不能揭示的信息。先通读全书再安排揭示，不因每章都要有游戏而改剧情。

## 3. 一幕一个主要故事动作

用`entry → action → visible result → observation/question → exit`定义每幕。一章可含数幕，不必强行把整章压成一次操作。动作不自然时用清楚的继续/进入按钮，配合真实场景改变，不用任意斜线冒充走路或拥抱。

## 4. 角色与场景基线

锁定角色表：年龄感、脸/发型、服装、身高比、动物结构、颜色、随身物。场景表：机位、地面、透视、主光源、对象坐标和UI安全区。先做一个角色参考与一组前/后状态图，通过后再扩展。

## 5. 先打通三幕样章

覆盖至少一次观察、一次实物操作、一次结果揭示，附一题理解题和明显但不突兀的音乐变化。检验鼠标/键盘、语音关闭时、刷新、双语和减少动态。先修坐标/存档/反馈，再大量生成素材。

## 6. 全书扩展

为每幕准备before/after图或局部动效；稳定机位，不对每个阶段从零重新抽图。背景烘焙人物适合整体状态切换；连续动作需要透明前景层与干净背景，不要移动整幅插图。逐章检查上一幕退出与下一幕进入。

## 7. 交付

输出完整可运行文件和可编辑数据，不只给截图。打包前白名单扫描、解压启动、检查资源、记录实际测试版本。原始稿、内部审阅记录与公开内容分目录。完整新书的视觉和教学质量仍需人工确认。
