# Rise of the Earth Dragon — source-required production profile

This profile is a production specification, not the book, a story transcription, or a ready-made adaptation. The reader supplies a readable copy they are permitted to use. Do not substitute model memory for missing pages. Do not distribute supplied source files with the toolkit.

Read [dm1-chapter-checkpoints.md](dm1-chapter-checkpoints.md) and [production-records.md](production-records.md) before expanding the book. Initialize with new_project.py --profile dm1; do not rename the demo.

## Inputs and output contract

- Read the supplied edition in full; establish its chapter/page map. Expect Book 1 with 16 chapters, but verify rather than silently forcing the count when the source differs.
- Produce the **same source story**, preserving event order, participants, causes, outcomes and unresolved questions. The UI, wording of short adapted cues, camera compositions and original score may differ. Do not replace it with the lighthouse demo.
- Write local project files: SOURCE.md, chapter-evidence.csv, character-bible.md, production.json, scene-state-table.json, music-cues.json, prompts.jsonl, art-provenance.json, editable runtime files and QA reports. Source excerpts stay in the user's private project; the public kit contains none.
- Scope: desktop illustrated reading, English with optional Chinese, scene actions, stable saved progress, event-driven instrumental music, short text dialogue, per-chapter understanding checks and optional retell. No default character voice, free walking or invented sequel.

## Character verification checklist

Extract and verify against the user's source and permitted visual references: Drake, Bo, Rori, Ana and Griffith; Worm, Vulcan, Shu and Kepri. Keep approved age/face/hair/clothing/size relationships stable. In particular check the distinctions between the brown legless Earth Dragon, red winged fire dragon, blue long-bodied wingless water dragon and white/gold winged sun dragon; do not treat green magical lighting as a new green dragon. Missing guide evidence is a declared gap, not a reason to invent identity.

## Source-grounded implementation checks

- Locations must visibly change before commands that require the new location; audit farm→castle transitions against the source.
- Do not turn failed training into a punishment game. Match the intended character response and emotional change.
- Use a clean background plus one transparent plate/prop where a reader carries an object; idle/drag/result must not duplicate it.
- For flight practice, verify the three different flight styles in the supplied chapter. Use actual independent sprites on designed rise/loop, circular and wave tracks if appropriate; keep the grounded dragon grounded. `assets/starter/track-flight.js` provides the portable mechanism, not character art.
- Distinguish dreams, memories and current events with explicit state changes. Hotspots must cover actual pictured soldiers or clues, not a nearby dragon's head.
- Match each light/power reveal to its precise source event. Separate illumination, warning, danger, power and successful escape; do not show solved obstacles in a pre-action image.
- Dialogue is story, not an answer key permanently beside the quiz. Ask for evidence/application and hide answer-bearing overlays while answering.
- Confirm the ending and unresolved mystery from the supplied book; do not end at a generic success screen or import later-book explanations.

## Drawing and score workflow

Run prompts.md B–D for verified identity sheets, before/after state images and independent sprites. Save reference IDs, exact final prompt, tool/settings/date, accepted output, changes and usage permissions. Whole-book art is not generated by the starter alone. Use original camera compositions, and do not copy the page layout of a reference book.

Run prompts.md F on the **actual extracted event table**, not a hard-coded chapter soundtrack. Suggested vocabulary: warm, wonder, night, warning, danger, power, relief. Map mood transitions to event IDs. Local procedural audio is a draft option; richer music uses the user's available tool/composer with recorded rights and human listening checks. Never require a particular paid service to open the result.

## Acceptance boundary

A matching source-story adaptation must pass chapter-by-chapter evidence comparison and actual browser reading. The toolkit's original demo tests mechanics only. No independent new-user full-book reproduction has yet been established by this candidate; don't label it "one-click identical book" or promise identical AI images/music.
